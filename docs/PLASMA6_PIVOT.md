# ADR: Canopy Plasma 6 pivot — 2026-11-27

Status: owner-authorized development direction; implementation and release acceptance NOT RUN. This document supersedes incompatible implementation priorities for new work on the Plasma integration track, not existing release/security gates or historical evidence.

## Decision and boundaries
Use upstream Plasma 6 and KWin, Qt 6/KF6 and their native extension points. Do not fork KWin/Plasma, run a second compositor, retain a redundant complete shell, duplicate upstream services, or turn a standalone ApplicationWindow into a fake desktop. Keep Canopy product identity and original Classic/Modern/future Shell Packs. Use Kubuntu 26.04 LTS as an isolated reference guest, not an irrevocable decision to change LacOS's Mint-derived goal. Mint 22.3 uses Noble, whose normal Plasma packages are 5.27; never mix incompatible repositories. Reassess final distro based on supported update/security lifecycle, upstream package compatibility, hardware, resource and recovery evidence.

Preserved baseline: integration/canopy-classic-20261123 at ec910d7a7275296ecbc8b5e5c459d356205165d1; new integration target integration/canopy-plasma6-20261127. Keep main, all prior branches, PRs, commit history, tests, evidence and original assets. Do not force-push, abandon uncommitted work, close old PRs indiscriminately, or merge to main. Finish/checkpoint in-flight tasks safely, classify each as reuse/port/reference/defer/superseded, then move available workers to new dependency-aware queue. Do not continue incompatible implementation simply to finish a task. Do not overwrite prior baseline or copy unverified branches blindly.

## Execution order
1. Inventory exact source and PR dependencies, original assets and license provenance; identify upstream substitutes, portable code and adapters. Keep a machine-readable migration matrix with evidence and exact SHAs. Prioritize executable work over expanding offline validation.
2. Establish a disposable Plasma 6 guest; verify ISO/source, packages, versions, GPU, Wayland session, baseline Cinnamon guest, logs and screenshots. Preserve existing Mint VM; use snapshots; do not modify host OS desktop, credentials or production systems. Start with distribution-supported packages and no extra PPAs.
3. Build a genuine Plasma 6 native Classic vertical slice: versioned plasmoid metadata, PlasmoidItem/containments, native top panel, floating dock, wallpaper, approved original icons, keyboard access and real window/application operations. Use upstream task manager and launch services (verify API stability and compatibility), not synthetic running-window state. Reuse QML items after extracting them from ApplicationWindow; preserve originals and optical corrections. Use actual Plasma session screenshot evidence.
4. Integrate existing upstream notification, tray, network, power, lock, display, launcher and settings services; use global menu when supported and a local-menu fallback. Avoid duplicate app index, notification daemon, power daemon, compositor or always-running preview. Use narrow adapters; prefer upstream stable APIs; isolate version-sensitive imports. Do not claim unsupported application behavior.
5. Package reversible user/session deployment using ownership-aware installs/uninstalls, backed-up layouts, no destructive resets or arbitrary scripts from untrusted packs. Keep native fallback desktop, preserve data, test upgrade/rollback/crash/restart/suspend and real application state.
6. Build Modern as another presentation on the same stack. Implement a trusted built-in Shell Pack manager, per-pack preferences, prepare/apply/verify/rollback lifecycle, monitor-aware layouts, no simultaneous full shells. Test repeated switches with apps open and no data loss or unbounded memory. Never describe layout scripts as sandboxing. Third-party executable QML/JS disabled until separate provenance/signing, isolation and permissions gates pass; no arbitrary community code execution.
7. Benchmark stock Mint, existing Canopy preview (clearly labeled), stock Plasma and minimal Plasma+Canopy on equal hardware and comparable workload. Measure system memory (available/used methodology), shell-process PSS, idle CPU, GPU, wakeups, boot/startup, responsiveness, power and sustained memory growth. Keep <=200 MiB incremental shell-owned PSS and <=1% idle CPU targets; verify full-system efficiency without disabling security/accessibility or essential functionality. Record versions, backend, exact SHA, commands, sample duration, raw logs; 5-minute idle, repeated cold boots, 24-hour soak and 100 round-trip switches where applicable. No claim of superiority before data.
8. Evaluate LacOS distribution choices separately after working Classic, Modern and switching; no ISO release until packaging, update, hardware, security, resource, recovery and owner visual gates pass.

## Priorities and governance
Preserve premium approved Classic identity, original icons and alpine-lake wallpaper, Tux branding, accessibility, high DPI and light/dark behavior. Do not redesign protected artwork or remove required features to improve benchmarks. No proprietary assets. Use Qt/Plasma native components where appropriate; keep modular event-driven code, bounded caches and no unnecessary background services. Retain current quality/reliability gate evidence; revalidate all relevant gates for new backend. Use independent reviewers, exact-SHA CI and actual guest evidence. Draft PRs against new integration branch; independent review and green applicable tests before integration there under existing delegated authority; never merge main. Preserve named holds #151/#278. Update architecture, README, quality, roadmap and QA status on the new track to eliminate conflicting obsolete instructions. No unsupported release, visual, performance or compatibility claims.

Hermes: maintain existing owner-approved host-safe workforce cap, do not increase concurrency. Start with bounded environment, native widget and migration tasks; independent QA joins as runtime is ready. Use isolated worktrees; assign blocked workers eligible reuse work; serialize heavy VM/build workloads on memory-constrained host. Keep commits/pushes, exact remote SHAs, evidence and recoverable checkpoints. First deliverable is an installed, genuinely interactive Plasma Classic slice, not another planning report. Do not stop at the creation of this ADR.
